# dsh-trellis-sun-doc-review

**大审**的执行入口。小审（S1–S4）随任务走，写在 `dsh-trellis-sun-feat` 的 review 阶段，
结论进 `review.md` 的「文档审查」节——**不要用本技能去顶替小审**。

维度定义、证据规则（位置 + 逐字引用 + 依据，无引用不成立）、报告骨架与不采用项**只在
`_templates/doc-review.md` 里定义**，本技能只讲怎么跑。执行前先读它。

## 什么时候用 / 不用

| 用 | 不用 |
|---|---|
| 版本冻结打板、文档定稿前 | 单个任务的两三份产物（走 feat 的小审） |
| 接手一批陌生文档，要先摸清结构与缺口 | 只想知道某段文字通不通顺（那是校对） |
| 需要跨文档一致性结论（同一事实在不同文档的表述） | 需要改代码里的行为（那是 feat / issue） |
| 需要一份可复核的文档体检报告 | 需要审查 PDF / DOCX（本插件没有文档读取工具） |

## 第一步：定范围（由配置与文件树算出）

范围不许凭印象列文件，按下面顺序算，并把推导过程记进报告 §8：

1. `.trellis/doc.json` 的 `files`（项目根相对路径）——这是运行时注入的权威清单；
2. 无配置时退回 legacy 口径：扫工程规范根（`$root`）下的 Markdown 树，即 `lib/spec.js` 的
   `listProjectSpecs`（`index.md` 优先，深度与数量有界）；
3. 加上仓库级文档：`README.md` / `README_EN.md` / `CHANGELOG.md`（存在即纳入）；
4. 加上本版本任务的产物：`.trellis/tasks/<slug>/*.md`（按版本范围选取，历史归档按需）。

范围里出现「文件不存在」时：记为范围缺口写进报告 §7，**不许静默跳过**。

## 第二步：清点与定位

- 每份文档归到 Diátaxis 四象限之一：tutorial / how-to / reference / explanation；一份文档承担多个象限时标出混装段落。
- 标受众：决策者 / 实施者 / 维护者。
- 建**覆盖图**：每份文档 × 章节一行，状态写「读到 / 跳过 / 无法读」，跳过的必须写原因。
  覆盖图有洞 = 本次审查未完成。

## 第三步：七维审查（D1–D7）

按 `_templates/doc-review.md` 的 D1–D7 逐维过，**判定权分离**成三张表：

- 事实表（D1 / D5）：查断言站不站得住。核不了的写「需外部核对：<要核对什么>」，**不许下结论、不许编造**。
- 语言表（D6）：查语法、术语、大小写、中英混排、歧义长句。不判技术对错。
- 结构表（D2 / D3 / D4 / D7）：查完整性、跨文档一致性、论证顺序、文档定位。不改技术细节。

每条意见给「位置 + 逐字引用 + 依据」；三样缺一即删掉，不算发现。

## 第四步：自证伪

准备判 P1 的每条发现，先写下「什么证据能推翻它」，然后试着推翻（回原文找反例、跑一次命令、查一次目标文件）。
推不翻才升 P1；推翻了降级或删掉。把「自证伪结论」写进发现表的对应列——这一列是这份报告值不值钱的证据。

## 第五步：出报告

落 `.trellis/reviews/<yyyy-mm-dd>-doc-review.md`（目录不存在则创建），骨架用
`_templates/doc-review.md` 的 8 节，顶部写 `status: draft`、`snapshot: <git rev-parse HEAD>`。

- `draft` 只是提案，**不许当结论用**；经人或 `dsh-trellis-sun-check` 复核后才改成 `confirmed`。
- 报告**不卡任何门禁**：它不改 `review.md` 的 blocking 判定，也不改 verified / human 两档。
- **不修改被审文档正文**——要改的话，交给对应工作流去改。

## 第六步：收尾

- 在 `.trellis/journal/<yyyy-mm>.md` 记一笔：跑了什么范围、结论（P1/P2/P3 各几条）、未覆盖部分、报告路径。
- 需要跟踪整改时，把 P1 条目交回对应任务（feat / issue）当验收项，**不要在建档里直接改文档**。

## 硬卡点

1. **覆盖图有洞** → 本次审查未完成，不许出报告。
2. **无引用的意见** → 删掉；把猜测写成发现等于伪造证据。
3. **编造**（页码、版本、工具名、计数、外部事实）→ 本次审查作废重跑。
4. **草案当结论**（`draft` 未复核就对外引用）→ 禁止。
5. **改被审文档** → 禁止；本技能只写报告与 journal。
6. **拿它顶替小审** → 禁止；小审是随任务的四维快审，大审不重扫小审已过完的条目。

## 取材与不采用

只抄维度与机制，不引入原材料项目的代码与运行时；出处、抄了什么、明确不采用什么（PDF/OCR 管线、
多厂商评审团、批注 UI、机械一致性对账与口径钉扎），统一记在 `_templates/doc-review.md` 末尾，不要在这里再抄一份。
